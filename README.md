# 语义相册 · Windows 本地版

打开就是相册，找东西的时候才搜索。**照片 / 视频 / 音频**都能用一句中文搜到，
全程本地计算，文件不联网、不上传。是 Redmi K40 服务器上那套 EmbeddingGemma-2 相册服务的
Windows 移植版（编码模型换成更适合 2G 显卡的中文 CLIP + Whisper）。

| 位置 | 作用 |

| 顶栏 **照片** | 首屏照片墙，按月份分组的瀑布式网格，滚到底自动加载更多 |
| 顶栏 **时刻** | 按「时间 + 地点」自动切出的事件（一次旅行、一场聚会），卡片式浏览 |
| 顶栏 **人像 / 城市 / 场景 / 事物** | 智慧相册四大分类，点卡片进分组看该类的全部照片 |

## 功能

| 功能 | 说明 |
|---|---|
| 照片墙 | 首屏按月分组，网格自动适应窗口宽度，滚到底无限加载 |
| 时刻 | 按拍摄时间连续性 + GPS 城市自动切事件，一次出行/一场聚会一张卡 |
| 智慧相册 | 人像（自动聚类、可命名、可纠错）、城市（照片 GPS）、场景、事物 四大类 |
| 其他面孔 | 有脸但样本太少（不够参与聚类的），单独收在一处，可手工认领 |
| 重复照片 | 感知哈希（dHash）找出同图多份/多版本，标出建议保留项，一键清理进回收站 |
| 找相似 | 灯箱里一键「找相似」，从当前这张出发找同类画面（不用重新上传） |
| 以文搜图 | 「雪地里的猫」「生日蛋糕」「海边的日落」… 中英文均可，**文件名命中额外加分** |
| 以图搜图 | 搜索浮层里上传一张图，找相册里相似的画面 |
| 视频搜索 | 抽 6 帧编码画面 + **音轨转文字**，可以搜「视频里说的话」 |
| 音频搜索 | 语音备忘录 / 录音 自动转文字，按内容搜索，结果里显示转写原文 |
| 语音搜索 | 点搜索浮层 🎤 说话，直接搜 |
| 最近搜索 | 搜过的话记在本机（最多 8 条），点一下就再搜一次，可一键清除 |
| 自动更新 | 后台每 5 分钟看一次目录，新文件自动建索引、自动归入相册 |

搜索结果是**分档**的：先给最相关的一档，其余折叠成「还有 N 项相关度较低 · 展开」——
语义检索总会把最像的几张排前面，后面的多半只是弱相关，不该一股脑铺满屏幕。

## 快速开始

1. 双击 `语义相册.exe`，**程序在后台运行，不弹黑窗口**。
   几秒后自动用 Edge 的 `--app` 模式开一个无地址栏的独立窗口，**没有 Edge 就退回默认浏览器**。
   - 窗口被误关：再双击一次程序图标即可，**不会起第二个实例**，只会把窗口拉回来。
   - 退出：**直接关掉窗口，后台进程一起退出**（离线索引、自动更新随之停止）。
     也可以点 ⋯ → **退出语义相册**（窗口关不掉、或从手机浏览器打开界面时用这个）。
   - 日志：`data\logs\app.log`（⋯ → **打开日志** 直达所在目录）；
     排障想看实时输出就跑 `语义相册.exe --console`。
2. 第一次打开点右上角 **⋯** → 在「照片文件夹」里输入或点快捷路径
   （如 `E:\相册`、`E:\相册\相机照片`、`此电脑\图片`）→ **添加**。
3. 点 **建立索引**。照片走独显（DirectML）约 **115 ms/张**；
   视频/音频慢在音轨转文字（Whisper，约 5-10 倍实时），可以放着不管，进度里有日志。
4. 索引完回到 **照片** 就是照片墙；点顶上的人像/城市/场景/事物前，
   先在 **⋯ → 智慧相册** 里点 `只更新标签 + 城市`（约 1 分钟）出分类，
   再 `全部重建` 扫人脸（人脸慢，每张约 0.2-0.5 秒，几百张几分钟）。
   「时刻」跟 `只更新标签 + 城市` 一起生成，点顶上 **时刻** 就能看。
5. 想清清硬盘：**⋯ → 重复照片 → 扫描**，会按感知哈希找出同图多份，
   标蓝框的是建议保留的，确认后其余移进 `data\trash\`（不是硬删，能拷回来）。

│  └─ face/          yunet.onnx + arcface.onnx（人脸）

- `models` 缺失时程序会提示；便携包从别人那拷的话，**整个 语义相册 文件夹拷走即可**。
- 想彻底重建索引：退出程序，删掉 `data/media.db`，重新打开再建索引。

## 技术说明

- **图文编码**：`chinese-clip-vit-base-patch16`（中文 CLIP，512 维）从 PyTorch 导出为
  ONNX 并 **int8 动态量化**，用 `onnxruntime-directml` 跑在 MX250 / Intel UHD 上
  （失败自动回退 CPU）。
- **onnxruntime 分级加载**（`app/ort_loader.py`）：DirectML 的执行器编在 `onnxruntime.dll`
  里，所以 `import` 阶段就会初始化 `DirectML.dll`，环境不支持时抛
  `DLL load failed ... 初始化例程失败`，整个程序连界面都起不来。
  现在的顺序是：**探测 `DirectML.dll` 能否 LoadLibrary → 能就用 DML 版，不能就改走
  `_internal/ort_cpu` 的纯 CPU 版**（两版各自独立目录，靠 `sys.path` 顺序 + pyd 同目录
  搜索隔离，不碰同名 DLL）。探测通过但 import 仍失败时还有一层回退。
- **独显加速的两个硬条件**（都踩过坑，见 `tools/README.md`）：
  1. vision 塔必须 **固定 batch=1** 导出——DirectML 对自由维度的 Reshape 直接抛 0x8007023E；
  2. 必须用 **经典 TorchScript 导出器**（`dynamo=False`）——torch 2.9 默认的 dynamo
     导出器产的图 DML 编译不了，会静默回落 CPU（等于买了个独显没用上）。
  实测 MX250：DML 115 ms/张 vs CPU 430 ms/张。
- **检索排序 / 显示分开**：文本塔（含语音转写）向量彼此夹角小，直接混排会让转写段霸榜，
  所以排序用「按模态分组做均值对齐」的校准分；界面上展示的百分比仍是**原始余弦**，
  校准分可能为负，人看不懂。类型筛选（照片/视频/音频）在排序阶段就剔除不匹配的行。
- **语音**：`faster-whisper tiny` int8 跑 CPU，音轨/音频 → 文字 → 文本塔向量。
  所以「音频」既能按说的内容搜到，卡片上还会显示转写的那句话。
- **人脸**：YuNet 检测（取 5 个关键点）→ **仿射对齐到 112×112 标准位** →
  ArcFace(`w600k_r50`) 512 维向量 → **质心聚类 + 平均连接合并 + 密度约束**。
  - 对齐是 ArcFace 能用的前提：它训练时看到的就是眼睛水平、脸宽固定的图。
    以前是「方框裁剪再拉伸」，同一个人的向量会散开，不同人反而因为构图相似而靠近。
  - 平均连接是为了杜绝**链式传染**：老算法用连通分量，只要 A≈B、B≈C 各自过阈值，
    A 和 C 哪怕完全不像也会被串成一簇 —— 这就是"八竿子打不着的两个人归到一起"的根因。
    现在两个簇要合并，不光看簇心，还要求**两簇成员的平均相似度**也够高。
  - **密度约束**（对齐 Immich 的 DBSCAN 思路）：一个人物至少要有 `FACE_MIN_FACES` 张
    相似的脸（默认 2）才承认。只有 1 张脸的分组多半是误检或路人，宁可不建。
    库里人脸总数少于 `FACE_SMALL_LIB`（默认 12）时自动降回 1 —— 新用户刚扫完
    二十张照片，人像页不该是空的。
  - 不够格的脸不删数据，标记成**未归类**收进人像页末尾的「其他面孔」，可以手工认领。
  - 同一张照片里同一个人只保留分数最高的一张（海报、动画截图里的卡通脸经常被连着检出来）。
  - 分组封面挑**质量分**最高的那张：`0.42×清晰度 + 0.38×检测分 + 0.20×正脸度`，
    清晰度用 Laplacian 方差归一化，正脸度看双眼的水平/垂直偏移。以前封面常挑到虚焦侧脸。
  - 编码方式变了（`FACE_VER`）会**自动整批重扫**，用户起过的名字按 (照片路径, 人脸框) 认领回来。
- **人工纠正**：识别再准也总有错，界面上留了三个口子 ——
  分组页每张照片左上角「✕ 不是他」（拆成单独一组 / 归到别人 / 别出现在人像里）、
  人物卡片「合并」（把整个分组并进另一个人）、人物卡片「命名」（同名自动合并）。
  **改过的分组会被锁住**：只要组里有一张脸是手工确认的，重聚类时整个组作为初始簇保留，
  不会再被算法拆散；纯手工拆出来的组则**不吸收新脸** —— 否则用户刚说完"这张不是他"，
  下次重建又给吸回去了。
- **时刻**：把全库按拍摄时间排序，相邻两张间隔超过 `EVENT_GAP`（默认 6 小时）就断开，
  短时间内拍的一串自动成一组（一次出行、一场聚会）；少于 `EVENT_MIN`（默认 3）张的段丢掉，
  免得满屏两秒钟的碎段。标题取「日期 + 该段 GPS 反查城市的众数」，没有 GPS 就只写日期。
- **重复照片**：64 位 **dHash**（缩到 9×8 灰度，比相邻像素亮度大小），汉明距离
  ≤ `PHASH_TH`（默认 6）判为同一张。全库两两比对是 O(n²)，所以用 **LSH 分桶粗筛**
  再并查集合并：把 64 位哈希切成 **阈值+1 段**（默认 6 → 7 段），
  —— 鸽笼原理：距离 ≤d 的两张哈希，切成 d+1 段必有一段完全相同，先按段分桶只比桶内。
  **段数必须跟着阈值走**，写死 4 段配阈值 6 只保证距离 ≤3 不漏，实测漏检 41.9%。
  单个桶超过 `DUP_BUCKET_MAX`（默认 200）就整个放弃 —— 纯色图会把桶撑爆，宁可漏检也不卡住。
  界面按「分辨率最高、其次文件最大」的规则推荐保留项，清理是**移进回收站**不是硬删。
- **搜索融合**：纯 CLIP 有个硬伤 —— 搜「IMG_2025」「D 盘那个旅行目录」这类"字面上的东西"
  它看不懂（向量空间里没有文件名的概念）。所以叠一条关键词通道，加分分三档：
  - 查询**整串**落在文件名里 → `+0.22`。用户就是在找这个名字，得让它稳稳排前面。
    实测反例：搜「IMG_20251207」，目标文件的语义余弦只有 0.36，比一张只是构图相似的图
    （0.38）还低，只加 0.05 的话它掉到第 5 名 —— 用户会觉得"我搜自己文件的名字都搜不到"。
  - 只落在路径（目录名）里 → `+0.12`，有用但不是铁证。
  - 分词命中 → 每词 `+0.05`，封顶 `0.12`，避免文件名巧合盖过语义主体。

  **最近搜索**存 `localStorage`（最多 8 条），纯本地不联网。
- **城市**：读照片 EXIF GPS → BigDataCloud 反查（需联网，仅此一步）；断网时只显示坐标。
- **场景/事物**：零样本分类，中文标签与整图向量算相似度取 top。
- **视频封面兜底**：分组封面按「整文件缩略图 → media 表里任一已存在的帧」顺序找，
  否则视频分组会显示成空白卡（缩略图是按帧时间存的，`md5(path)` 那个 key 并不存在）。

### 内存 / 速度（RedmiBook 14 · 8GB · MX250 2G 实测口径）

- CLIP 常驻约 300MB，Whisper 按需加载约 200MB，总占用 < 1.5GB。
- 图片视觉编码：DML 115 ms/张；CPU 430 ms/张。
- 搜索一次（编码一句话 + 全库点乘）：毫秒级；「找相似」多一次图片编码，约 1 秒。

### 可调参数（环境变量，不设就用默认）

| 变量 | 默认 | 作用 |
|---|---|---|
| `FACE_MIN_FACES` | `2` | 一个人物至少要有几张相似的脸才成立。调大 → 人物更少但更准 |
| `FACE_SMALL_LIB` | `12` | 人脸总数低于这个数时自动放宽到 1 张（保护新库不空） |
| `FACE_TH` | 见代码 | 人脸相似度阈值，识别过严/过松时微调 |
| `PHASH_TH` | `6` | 重复照片的汉明距离阈值，调大召回更多但也更容易误判（分段数会跟着变） |
| `DUP_BUCKET_MAX` | `200` | 单个 LSH 桶的候选上限，超过就放弃该桶（防纯色图把桶撑爆） |
| `EVENT_GAP` | `6` | 时刻切分的时间间隔（小时），调小事件更细碎 |
| `EVENT_MIN` | `3` | 一个时刻最少几张才保留 |
| `AIWIN_ORT` | 自动 | 设成 `cpu` 强制走纯 CPU，跳过 DirectML 探测 |

例：`set FACE_MIN_FACES=3` 再启动程序。

## 常见问题

- **打开后没反应**：再双击一次程序图标（会把已启动实例的窗口拉出来）；
  仍不行看 `data\logs\app.log` 末尾。端口默认从 8765 起自动找空闲的。
- **手机/平板想一起用**：同一局域网内访问 `http://<电脑IP>:8765` 即可
  （只读搜索；删除/命名会直接动电脑上的文件，慎点）。
- **Windows Defender / SmartScreen 提示**：个人打包未签名程序，选「更多信息 → 仍要运行」。
- **删除的文件去哪了**：移到 `data\trash\日期\`，可以从那拷回去。
- **模型标签显示「CPU 模式」**：说明独显加速没生效（驱动异常/卡被占满），功能不受影响。
- **`ImportError: DLL load failed ... 动态链接库(DLL)初始化例程失败`**：
  `onnxruntime-directml` 的 DirectML 执行器是编译进 `onnxruntime.dll` 的，`import` 那一步
  就会初始化 `DirectML.dll`，而它要 D3D12 设备——**远程桌面会话、虚拟机、老驱动、
  Win7/8** 都会在这里失败，等于整个程序起不来。
  现在 `ort_loader.py` 会先单独探测 `DirectML.dll`，探不到就**直接切到内置的纯 CPU 版**
  （`_internal/ort_cpu/`，31MB），一次都不会碰 DirectML 那条路。
  界面「模型」会显示 `CPU 模式（DirectML 不可用，已自动降级）`，功能相同，编码慢 3-4 倍。
  想手动强制：`set AIWIN_ORT=cpu` 再启动。
- **某个分组封面是空白**：先点一次 `⋯ → 智慧相册 → 只更新标签 + 城市` 重建封面缓存。

## 从源码运行（开发者）

仓库里**只有源码和文档**：模型权重（700MB+）、`release/` 构建产物、`data/` 运行数据
都被 `.gitignore` 排除了。想自己跑起来，三步：

### 1. 依赖

```bash
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
```

要导出 ONNX 模型、打 exe，再装 `pip install -r requirements-dev.txt`。

### 2. 模型从哪来

| 目录 | 需要的文件 | 怎么获取 |
|---|---|---|
| `models/clip/` | `vision.onnx`（int8，约 87MB）、`text.onnx`（fp32） | 把 `chinese-clip-vit-base-patch16` 的 PyTorch 权重放到 `models_src/clip_cn/`，跑 `python tools/export_clip.py`（自动量化 + torch↔onnx 一致性校验）。`vocab.txt` 仓库里已带 |
| `models/whisper/` | `model.bin`（faster-whisper tiny int8） | 其余三个小文件（`config.json` / `tokenizer.json` / `vocabulary.txt`）仓库里已带 |
| `models/face/` | `yunet.onnx`（人脸检测）、`arcface.onnx`（w600k_r50，约 174MB，人脸特征） | InsightFace 的 buffalo_l 模型包，或 `tools/pull_face.py` 从别的机器拉（需设 `PHONE_PASS` 环境变量） |

缺文件时界面会直接提示，不会静默出错。

### 3. 跑起来

```bash
# 只要服务，浏览器打开 127.0.0.1:8765
python -m uvicorn app.server:app --port 8765

# 桌面形态：起服务 + 开 Edge --app 窗口 + 关窗即退出（和 exe 行为一致）
python app/win_main.py
```

第一次打开在 **⋯ → 照片文件夹** 里加一个目录，就开始建索引。

> `app/` 是 FastAPI 服务 + 单文件前端（`index.html`）+ 桌面入口（`win_main.py`）；
> `installer/` 是一键安装包（Tk 向导，兼静默安装/卸载）；`tools/` 是导出模型、打包、
> 验收脚本，细节见 `tools/README.md`。

## 重新打包（开发）

```
python tools/export_clip.py     # 从 models_src 原始权重导出 ONNX+int8 并校验
python tools/build.py           # PyInstaller onedir → release/pkg + release/out/语义相册.zip
python tools/build_installer.py # 一键安装包 → release/out/语义相册Setup.exe
```

产物统一放 `release/out/`，`release/pkg/` 是 onedir 运行目录（打包中间产物，zip 内映射回 `语义相册/`）。
